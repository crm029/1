# سامانه کلینیک نایریکا

نسخه مستقل کد سامانه مدیریت و رزرو کلینیک.

## پیش از نصب

این مخزن شامل کد برنامه است و **جایگزین بکاپ دیتابیس نیست**. برای انتقال کامل سامانه، این موارد را جداگانه نگه دارید:

1. فایل ZIP همین مخزن از شاخه `main`
2. آخرین بکاپ SQL دیتابیس از پنل سامانه
3. آخرین بکاپ کامل فایل‌ها از پنل سامانه
4. فایل تنظیمات محرمانه سرور که در مخزن قرار نمی‌گیرد

## راه‌اندازی

1. فایل ZIP را استخراج کنید.
2. از `config/config.example.php` یک کپی با نام `config/config.local.php` بسازید.
3. اطلاعات دیتابیس را در `config/config.local.php` وارد کنید.
4. بکاپ SQL را در دیتابیس مقصد با phpMyAdmin یا ابزار مدیریت دیتابیس وارد کنید.
5. پوشه‌های `public/uploads` و `storage` باید برای کاربر PHP قابل نوشتن باشند.
6. دامنه باید به پوشه پروژه متصل باشد تا فایل `.htaccess` ریشه درخواست‌ها را به `public/` هدایت کند؛ یا Document Root مستقیماً روی `public/` تنظیم شود.
7. افزونه‌های PHP موردنیاز شامل PDO MySQL، cURL، Fileinfo، mbstring و ZipArchive فعال باشند.

## تنظیمات محرمانه سرور

این مقادیر را در متغیرهای محیطی هاست یا در بخش `secrets` فایل محرمانه `config/config.local.php` تنظیم کنید؛ آن‌ها را داخل Git یا فایل عمومی قرار ندهید:

- `DB_HOST`
- `DB_NAME`
- `DB_USER`
- `DB_PASS`
- `APP_URL`
- `NAYRICA_BOT_API_KEY`
- `NAYRICA_MEDIA_SECRET`

در روش فایل محلی، کلیدها را در بخش `secrets` با نام‌های `bot_api_key`، `media_secret` و `cron_secret` وارد کنید. فایل `config.local.php` در Git نادیده گرفته می‌شود.

`NAYRICA_BOT_API_KEY` باید با کلید تنظیم‌شده در سرویس دریافت‌کننده ربات بله یکسان باشد. پس از چرخش کلید، هر دو سمت را به‌روزرسانی کنید.

`NAYRICA_MEDIA_SECRET` برای لینک‌های موقت و امضاشده تصاویر خصوصی مشتریان و کارکنان استفاده می‌شود. آن را یک مقدار تصادفی قوی و مستقل انتخاب کنید.

## Cron بکاپ خودکار

مسیر Cron برابر است با:

`POST https://YOUR-DOMAIN/cron/backup`

پارامتر `secret` باید در بدنه POST و برابر مقدار `NAYRICA_CRON_SECRET` باشد. درخواست GET پشتیبانی نمی‌شود.

## فایل‌ها و حریم خصوصی

- فایل‌های داخل `public/uploads/clients` و `public/uploads/users` از دسترسی مستقیم وب مسدود شده‌اند و باید از لینک امضاشده `public/media.php` خوانده شوند.
- `config/config.local.php`، فایل‌های بکاپ، فایل‌های ZIP و آپلودهای جدید در Git نادیده گرفته می‌شوند.
- بکاپ کامل برنامه، تنظیمات محرمانه زنده و تاریخچه Git را در ZIP قرار نمی‌دهد.
- بکاپ کامل فایل‌ها به‌تنهایی شامل دیتابیس نیست؛ فایل SQL را جداگانه نگه دارید.
- بعد از بازیابی، تنظیمات محرمانه را دوباره در سرور وارد کنید.

## چک‌لیست بعد از انتقال

- ورود سوپرادمین و تغییر رمز اولیه
- مشاهده و ویرایش پرونده مشتری و تصاویر مدارک
- مشاهده رسید پرداخت در پنل و از طریق ربات
- تست رزرو و جلوگیری از رزرو هم‌زمان
- تست پیام بله و پیامک ۰۰۹۸
- تست ثبت و تسویه نوبت، حقوق و پورسانت
- ساخت و بازیابی بکاپ SQL و فایل‌ها
- تست Cron با درخواست POST
- بررسی لاگ خطاهای PHP و وب‌سرور

تست نهایی روی هاست واقعی و دیتابیس عملیاتی باید پس از استقرار انجام شود؛ موفقیت دریافت ZIP به‌تنهایی تأییدکننده سلامت اجرا نیست.
